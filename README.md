### Задание 3: Состояние + обработка ввода

Сделай форму с инпутом:
пользователь вводит текст
этот текст сохраняется в useState
отображается ниже в <p>
👉 Цель: научиться обновлять состояние на основе onChange.

Конечно! Давай разберём подробно, что делает атрибут `value` в React и почему он важен.

---

### 🔹 1. Контролируемый vs неконтролируемый input

1. **Неконтролируемый input**

```jsx
<input type="text" />
```

* React **не управляет** его значением.
* Значение хранится только в DOM.
* Чтобы получить текст, нужно обращаться к `ref` или `e.target.value` при событии.

2. **Контролируемый input**

```jsx
const [text, setText] = useState('');
<input type="text" value={text} onChange={(e) => setText(e.target.value)} />
```

* React **управляет** значением input через состояние (`text`).
* Любое изменение текста происходит **только через setText**, компонент рендерится заново и input получает актуальное значение.
* Это даёт полный контроль над вводом: валидация, очистка, форматы, маски.

---

### 🔹 2. Почему `value` нужен

* **Связь с состоянием**: React знает текущее значение input.
* **Гарантия актуальности UI**: если состояние обновляется из других мест, input автоматически меняется.
* **Предотвращение несинхронности**: без value может быть расхождение между тем, что React думает, и тем, что в DOM.

Пример:

```jsx
const [text, setText] = useState('');

const clearInput = () => setText('');

return (
  <>
    <input value={text} onChange={e => setText(e.target.value)} />
    <button onClick={clearInput}>Очистить</button>
  </>
);
```

* Кнопка «Очистить» срабатывает мгновенно, потому что React управляет состоянием input.
* Без `value={text}` кнопка не очистит поле в DOM, только состояние React — получится рассинхрон.

---

### 🔹 3. Итог

* **value** связывает **DOM-элемент input** со **состоянием React**.
* Это основа **контролируемых компонентов** — правильная практика для форм.

```ts
type Task = {

const [taskList, setTaskList] = useState<Task[]>([]);
```

```ts
const handleChange = (e: React.ChangeEvent<HTMLInputElement>): void => {
```

```ts
type TodoProps = {
```

### 4️⃣ Типизация map и key

```ts
taskList.map((task: Task) => <li key={task.id}>{task.text}</li>)
```

* `task` явно типизирован как `Task`.
* `key` — уникальный идентификатор, желательно **не индекс массива**, чтобы React корректно отслеживал изменения.

* Для кнопок и событий используем `React.MouseEvent<HTMLButtonElement>`

### Задание 9: Список задач с отметкой выполнено
Есть массив задач { id, text, done }.
Рендерим список <ul> с чекбоксами.
При клике на чекбокс задача помечается выполненной (done = true/false).
Стиль выполненных задач меняется (например, зачёркнут текст).
Хуки: useState.
Реальная ситуация: todo-листы, чекбоксы на сайте.


### 1️⃣ Структура состояния

```ts
const [tasks, setTasks] = useState<Task[]>([]);
const [newTask, setNewTask] = useState<string>('');
```

* `tasks` — массив объектов `Task` с полями `id`, `text`, `isDone`.
* `newTask` — текущее значение инпута для добавления новой задачи.
* Всё состояние хранится через `useState`, что стандартно для React-фронтенда.

✅ **Плюс**: использован тип `Task`, типизация строгая — удобно масштабировать.

---

### 2️⃣ Добавление задач

```ts
const addTask = () => {
    if (newTask.trim() === '') return;

    const task: Task = {
        id: Date.now(),
        text: newTask,
        isDone: false,
    };
    setTasks(prev => [...prev, task]);
    setNewTask('');
};
```

* Проверка пустой строки → предотвращает добавление пустых задач.
* `id: Date.now()` гарантирует уникальность ключей.
* Используется **иммутабельное обновление массива** через spread `[...prev, task]`.
* После добавления input очищается → удобный UX.

✅ **Плюс**: всё чисто и по React-паттерну.

---

### 3️⃣ Переключение статуса задачи

```ts
const toggleTask = (id: number) => {
    setTasks(prev =>
        prev.map(task =>
            task.id === id ? { ...task, isDone: !task.isDone } : task
        )
    );
};
```

* Используется `map` + spread → иммутабельное обновление конкретного объекта в массиве.
* Клик по задаче меняет только её `isDone` → остальные задачи не затрагиваются.

✅ **Плюс**: правильная иммутабельная логика, подходит для Redux/TS-подходов.

---

### 4️⃣ Рендеринг списка

```tsx
<ul style={{ listStyle: 'none', padding: 0 }}>
    {tasks.map(task => (
        <li key={task.id}>
            <span
                onClick={() => toggleTask(task.id)}
                style={{
                    textDecoration: task.isDone ? 'line-through' : 'none',
                    color: task.isDone ? 'gray' : 'black',
                    cursor: 'pointer',
                    userSelect: 'none',
                    display: 'inline-block',
                    padding: '4px 0',
                }}
            >
                {task.text}
            </span>
        </li>
    ))}
</ul>
```

* Клик по `<span>` переключает `isDone`.
* Инлайн-стили управляют зачёркиванием и цветом → **нет необходимости в CSS-классе**.
* `key={task.id}` → правильно, предотвращает лишние ререндеры списка.

✅ **Плюс**: простой, полностью контролируемый список задач.

---

### 5️⃣ Input и кнопка

```tsx
<div style={{ display: 'flex', gap: '8px', marginBottom: '12px' }}>
    <input
        type="text"
        value={newTask}
        placeholder="Введите задачу"
        onChange={(e) => setNewTask(e.target.value)}
        style={{ flex: 1, padding: '4px' }}
    />
    <button onClick={addTask}>Добавить задачу</button>
</div>
```

* Контролируемый input → значение хранится в `useState`.
* Кнопка вызывает `addTask` → добавление новой задачи.
* Стилизация через flex → простая, современная верстка.

✅ **Плюс**: UX удобен, input растягивается по ширине, кнопка рядом.

---

### 6️⃣ Возможные улучшения для продакшена

1. **Вся зона `<li>` кликабельна** (не только `<span>`).
2. Добавить возможность **удалять задачи**.
3. Добавить **сортировку или фильтры** (все/выполненные/активные).
4. Сохранение задач в **localStorage** → при перезагрузке не теряются.
5. Использовать **CSS или Tailwind** для более чистой стилизации вместо инлайн-стилей.

* Инлайн-стили подходят для небольшого проекта, для продакшена можно вынести в CSS.
* Логика добавления, переключения задач полностью рабочая.
